**Target Scope**: `game.js`, `assets/game.js`, Test Suites (`test_currency_save.js`, `test_gating_quests.js`, `test_r3_r4_systems.js`)
**Auditor/Challenger**: Challenger 1 (`challenger_m1_1`)

## Challenge Summary

**Overall risk assessment**: **MEDIUM**

While all mandatory Node.js test scripts (`test_currency_save.js`, `test_gating_quests.js`, `test_r3_r4_systems.js`) and syntax checks (`node -c game.js`, `node -c assets/game.js`) passed 100% cleanly, empirical code analysis uncovered two key implementation flaws in runtime sprite rendering and texture initialization:

1. `PixelArtRenderer.generateAllTextures(scene)` (lines 117–1565) is **NEVER CALLED** inside any active game scene (`FarmScene`, `FishingScene`, `ArcadeScene`, `DungeonScene`), leaving the 48x48 procedural sprite rendering system as dead code during runtime.
2. Emoji text sprites remain for game entities in `FishingScene` (L88: `add.text(..., '🐟')` for active fish entity in reel minigame) and `FarmScene` (L3764: `add.text(..., CROP_ICONS[i%5])` for crop plot entity labels).

## Challenges

### [High] Challenge 1: `PixelArtRenderer` is Never Invoked in Game Scene Initialization

- **Assumption challenged**: The newly introduced 48x48 pixel art sprite generator `PixelArtRenderer` is active and populating texture memory for runtime scenes.
- **Attack scenario**: Code analysis of `game.js` and `assets/game.js` shows `class PixelArtRenderer` is defined (L117–1565), but `PixelArtRenderer.generateAllTextures(this)` is **never invoked** in `preload()` or `create()` of `FarmScene`, `FishingScene`, `ArcadeScene`, or `DungeonScene`. Instead, `FarmScene` falls back to its legacy `_bakeTextures()` method, while other scenes assume textures exist.
- **Blast Radius**: The 1,400+ lines of procedural 48x48 sprite generation logic (`player_walk_*`, `crop_*`, `fishing_*`, `arcade_*`, `dungeon_*`) are unused in actual gameplay. Any scene booted without prior legacy texture creation will crash or fail to load entity textures.
- **Mitigation**: Add `PixelArtRenderer.generateAllTextures(this);` inside `create()` or `preload()` of all game scenes (or a shared scene base hook).

---

### [Medium] Challenge 2: Emoji Text Sprites Remain for Game Entities in `FishingScene` & `FarmScene`

- **Assumption challenged**: Zero emoji text sprites remain for game entities across `FarmScene`, `FishingScene`, `ArcadeScene`, and `DungeonScene`.
- **Attack scenario**: 
  1. In `FishingScene` line 88, the moving fish entity on the tension reel bar is created using a Phaser text sprite with emoji `"🐟"`:
     `this.fishIcon = this.add.text(this.barX, this.fishIconY, '🐟', {fontSize:'26px'})`
  2. In `FarmScene` line 3764, crop plot labels are created using Phaser text objects with emojis:
     `this.add.text(p.x, p.y + PLOT_SIZE/2 + 3, CROP_ICONS[i%5], {fontSize:'18px'})`
- **Blast Radius**: Violates the Milestone R1 mandate to replace all game entity emoji text sprites with procedural pixel art sprites/textures.
- **Mitigation**: 
  - Replace `this.add.text(..., '🐟')` in `FishingScene` with `this.add.image(..., 'fishing_salmon')` (or the specific caught fish key generated by `PixelArtRenderer`).
  - Replace `CROP_ICONS` text emojis in `FarmScene` with procedural crop icons generated by `PixelArtRenderer`.

---

### [Low] Challenge 3: Dual File Desynchronization Risk (`game.js` vs `assets/game.js`)

- **Assumption challenged**: `game.js` and `assets/game.js` are guaranteed to remain synchronized during future modifications.
- **Attack scenario**: While empirical verification confirms `game.js` and `assets/game.js` are currently 100% byte-for-byte identical (281,620 bytes), future developer updates to `game.js` without copying to `assets/game.js` will cause runtime desynchronization in web servers loading from `assets/`.
- **Blast Radius**: Subtle desync bugs between root development code and assets directory.
- **Mitigation**: Establish an automated build/copy script or git pre-commit hook to maintain strict 1:1 parity between `game.js` and `assets/game.js`.
